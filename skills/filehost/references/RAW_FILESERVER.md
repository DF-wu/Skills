## 1. What it does

Serves the content of a Nextcloud **public link share** (share type 3) as is: correct `Content-Type`, no
Nextcloud UI, no cookies, a strict CSP, streaming, 304 support. A folder share automatically serves its
`index.html`. Uses: static sites, report pages, direct links to images, JSON, RSS and other assets.

## 2. Routes

`ncloud occ -- router:list files_sharing_raw` (Nextcloud core grants the `/raw` and `/rss` root routes to this app
since 32.0.7 / 33.0.1):

| Method | Path | Meaning |
|---|---|---|
| GET | `/raw/{token}` | the shared node; folder -> its `index.html` |
| GET | `/raw/{token}/{path}` | a file inside a folder share; if `{path}` is a folder -> that folder's `index.html` |
| GET | `/raw/u/{userId}/{path}` | the logged-in user's own files (session or Basic auth; own files only) |
| GET | `/rss`, `/rss/{path}` | the share whose token is literally `rss` (requires custom public share tokens; `ncloud doctor` shows `custom_tokens` in the `sharing` row) |
| GET | `/apps/files_sharing_raw/{token}[/{path}]`, `/u/...`, `/rss...` | legacy, always 307 to `/raw/...` |
| GET | `/apps/files_sharing_raw/api/v1/raw-share/{shareId}` | read raw state |
| POST | `/apps/files_sharing_raw/api/v1/raw-share/{shareId}` | set raw state |
| GET | `/apps/files_sharing_raw/api/v1/raw-shares/{fileId}` | all link shares of a file/folder with their raw state |
| GET | `/apps/files_sharing_raw/api/v1/raw-public-url?token=` | observed 500 on Nextcloud 33 with 0.7.3 (the route points at a missing controller); do not use |

Without custom tokens, tokens are generated by Nextcloud and cannot be chosen.

## 3. Which shares are served (allowlist model)

Only **public link shares** (type 3) whose token is **explicitly allowed** are served. Either source is enough:

1. **System config** (always checked first): `allowed_raw_tokens` (exact token array) and
   `allowed_raw_token_wildcards` (`*` wildcards).
2. **DB registry** (table `oc_raw_shares`): the "Enable raw link" toggle in the Files sidebar, or the API
   `POST raw-share/{id}` with `enabled=1` (what `ncloud raw enable` and `filehost publish` use).

Not allowed, unknown token, not a link share, or file lookup failed -> always **`404 Not found` (text/plain,
9 bytes, no cookie)**. This 404 comes from the app; a Nextcloud HTML 404 means no route matched. Tell them
apart by content-type.

## 4. API

All endpoints need an authenticated user; Basic auth plus `OCS-APIRequest: true` passes the CSRF check. Only
the share's **creator or owner** can use them.

```bash
AUTH='alice:<app-password>'; H='OCS-APIRequest: true'; NC=https://cloud.example.com
curl -s -u "$AUTH" -H "$H" "$NC/apps/files_sharing_raw/api/v1/raw-share/<share_id>"
# {"shareId":<share_id>,"enabled":false,"csp":null,"rawOnly":false,"canEditCsp":true,"token":"<token>","rawUrl":"https://cloud.example.com/raw/<token>"}

curl -s -u "$AUTH" -H "$H" -X POST "$NC/apps/files_sharing_raw/api/v1/raw-share/<share_id>" \
  -d enabled=1 -d rawOnly=0 --data-urlencode "csp=default-src 'self'"
# same JSON shape. enabled=0 keeps the row and the CSP (a later enable without csp reuses it); rawOnly is not kept, see below

curl -s -u "$AUTH" -H "$H" "$NC/apps/files_sharing_raw/api/v1/raw-shares/<fileid>"
# {"fileId":<fileid>,"shares":[{"shareId":<share_id>,"token":"<token>","enabled":true,"rawUrl":"..."}]}
```

The CLI wraps these: `ncloud raw get <share_id>`, `ncloud raw enable <share_id> [--preset P | --csp C]
[--raw-only | --no-raw-only]`, `ncloud raw disable <share_id>`, `ncloud raw list <path>`,
`ncloud raw url <share_id> [path]`.

POST parameters:

- `enabled`: `1/true/yes/on` or `0/false/no/off`.
- `rawOnly`: **absent means false** (it switches a previous rawOnly off). While a share is disabled, GET always
  reports `rawOnly:false` and `csp:null` (the CSP is still stored). So `ncloud raw enable` without
  `--raw-only/--no-raw-only` keeps the current value when the share is **currently enabled** (it reads it
  first), and sends false when the share is **currently disabled** (e.g. after `raw disable`) - pass
  `--raw-only` again. `filehost publish` behaves the same (`--raw-only` / `--show-share-page`).
- `csp`: absent = unchanged (also kept across disable -> enable); empty string = cleared (back to the fallback).
  Only members of `csp_editor_group` (app config, default `admin`) can change it; for anyone else the value is
  ignored and the old one kept. Max 8192 characters, control characters are stripped; **directive names are not
  validated** (see CSP.md section 1).
- 404 `{"error":"not_found"}`: the share does not exist, is not a link share, or is not yours.

`ncloud raw enable` always prints a stderr warning (raw is fully public, the share password is not checked).
It is a reminder, not a block.

## 5. Response headers, caching, conditional requests

Observed for `GET /raw/<token>/index.html` (where the last four headers come from: see the first bullet below):

```
content-type: text/html; charset=utf-8            # charset added for text/* and *xml; otherwise the Nextcloud mimetype
etag: "<hex mtime>-<hex size>"                     # falls back to md5(content) without mtime/size
last-modified: <file mtime, HTTP date>
cache-control: public, max-age=300, stale-while-revalidate=30, stale-if-error=86400
content-security-policy: ...                       # see CSP.md
x-content-type-options: nosniff                    # added by Nextcloud core
x-robots-tag: noindex, nofollow                    # added by core; raw pages are not indexed
x-frame-options: SAMEORIGIN                        # added by core; browsers prefer CSP frame-ancestors when present
referrer-policy: no-referrer                       # added by core
(no set-cookie; no Access-Control-Allow-Origin)
```

- The "added by core" headers are Nextcloud's security headers sent on every response (on AIO via
  `Header always set` in the web root `.htaccess`; without mod_headers `base.php` `addSecurityHeaders()` adds
  them). Observed on Nextcloud 33: the `/raw/u/` 200 and the `/raw/<token>` 404 both carry `x-robots-tag`;
  the `/raw/<token>` 404 also carries `x-frame-options` and `referrer-policy`.
- **No CORS headers**: raw responses send no `Access-Control-Allow-Origin` (the raw controller has no CORS
  annotation; inferred from the source). Browser `fetch()` from another origin cannot read the content;
  `<img>`, plain `<script>` / `<link>` and server-side clients are unaffected. Raw pages on the same Nextcloud
  host are same-origin and can fetch each other.
- `If-None-Match` / `If-Modified-Since` -> **304** (observed).
- `HEAD` returns headers only.
- Files without an extension, or with mimetype `application/octet-stream`, are sniffed with finfo (first
  32 KiB).
- Normal GETs stream (`fopen` -> `php://output`); large files do not use much memory.
- Private `/raw/u/` responses use `cache-control: private, max-age=0`.

## 6. URL shapes and trailing slashes

| URL | Result (observed unless noted) |
|---|---|
| `/raw/<token>` | 200, the folder's `index.html` |
| `/raw/<token>/` | **404 (Nextcloud HTML 404)**: `{path}` needs at least one character, no route matches |
| `/raw/<token>/index.html` | 200 - the recommended canonical URL |
| `/raw/<token>/sub` | 200, `sub/index.html` |
| `/raw/<token>/sub/` | 200, `sub/index.html` |
| `/raw/<token>/assets/app.js` | 200 `application/javascript` |
| `/raw/<token>/nope.txt` | 404 text/plain |
| `/raw/<token>` (folder share **without** `index.html`) | **200 `application/json`, body `null`** (not a 404); files inside, e.g. `/raw/<token>/x.txt`, are 200 as usual |
| `/raw/<token>/sub/` (`sub` exists, no `index.html`) | same, 200 `null` (same code path; inferred from the source, not observed) |
| `/raw/<token>/missing-dir/` | 404 text/plain |
| `/apps/files_sharing_raw/<token>/x` | 307 -> `/raw/<token>/x` |

Consequence: on `/raw/<token>` the browser resolves relative paths against `/raw/`, so `href="style.css"`
becomes `/raw/style.css` -> 404. Fixes, pick one: use `/raw/<token>/index.html` as the canonical URL (what
`filehost url` prints); `--inject-base` (inserts `<base href=".../raw/<token>/index.html">`, `#anchor` links
keep working); or absolute paths in the page. Always give sub-folders a trailing slash
(`filehost url <name> docs/` keeps it and percent-encodes the path).

Why `200 null`: `RawResponse::returnRawResponse()` returns a `NotFoundResponse` when there is no `index.html`,
but the controller calls it without `return`, so the serialized result is `null`. Content-type is therefore
`application/json` with status 200 - checks must look at the content-type, not just the status. `filehost
publish` on a folder without `index.html` sets `url` to the first file and verifies that file; `filehost list`
points `url` at the first file as well and adds `base` (`/raw/<token>`) and `has_index: false`.

## 7. rawOnly, password, expiry, deletion

- `rawOnly=true`: a global middleware makes `/s/<token>` (and its `/download` etc.) return 404. System config
  `raw_only_tokens` / `raw_only_token_wildcards` does the same. Being in `raw_only_tokens` does not *allow*
  raw serving - that is still section 3. The DB rawOnly only applies while raw is enabled; after
  `raw disable` -> enable it is false unless `rawOnly=1` is sent again (section 4).
- **The share password is not checked**: the controller calls `getShareByToken()` and serves the node. A raw
  link is public, full stop.
- Expired shares: core checks expiry when resolving the token (the share is removed) -> raw 404.
- Deleting the share (OCS DELETE): `ShareDeletedListener` removes the registry row -> raw 404 immediately
  (observed).
- A folder can have several link shares (`multiple_links=true`); each token is toggled separately, which allows
  URL rotation.

## 8. System config (occ)

All `config:system:*` (needs occ; see nextcloud-use `references/OCC.md`):

| Key | Default | Purpose |
|---|---|---|
| `allowed_raw_tokens` | `[]` | exact token allowlist (checked before the DB) |
| `allowed_raw_token_wildcards` | `[]` | wildcard allowlist |
| `raw_only_tokens` / `raw_only_token_wildcards` | `[]` | hide the `/s/` page |
| `raw_csp` | unset | CSP rule table (see CSP.md) |
| `raw_cache_public_max_age` | 300 | `max-age` seconds for public raw |
| `raw_cache_public_stale_while_revalidate` | 30 | 0 disables |
| `raw_cache_public_stale_if_error` | 86400 | 0 disables |
| `raw_cache_private_no_store` | false | `no-store` for `/raw/u/` |
| `raw_sendfile_backend` | off | offload with `apache` (X-Sendfile) or `nginx` (X-Accel-Redirect); the AIO Apache has no mod_xsendfile, keep `off` there |
| `raw_sendfile_nginx_prefix` / `raw_sendfile_allow_private` / `raw_sendfile_min_size_mb` | | sendfile details |

Examples:

```bash
ncloud occ --yes -- config:system:set raw_cache_public_max_age --type=integer --value=30
ncloud occ --yes -- config:system:set allowed_raw_token_wildcards 0 --value='site-*'   # arrays use an index
ncloud occ -- config:system:get raw_cache_public_max_age        # exit 1 = unset
ncloud occ -- config:app:get files_sharing_raw csp_editor_group  # empty = default admin
```

These are instance-wide changes; they need the user's consent.

## 9. Private raw (`/raw/u/`)

`/raw/u/alice/Documents/x.html` works only for the **logged-in `alice`** (Basic auth works, observed 200); a
`userId` other than the logged-in user -> 404. It is a self-preview, not a public URL. CSP applies as well (use
`raw_csp` `path_prefix` / `extension` rules).

## 10. Observed test matrix (Nextcloud 33, files_sharing_raw 0.7.3; test shares removed afterwards)

- Folder link share created with `permissions=1` is reported as `17` (read + share); `raw-share` POST
  `enabled=1` -> 200; `/raw/<token>` 200; `/raw/<token>/` HTML 404; `/s/<token>` 200, then 404 after
  `rawOnly=1`.
- Overwriting `style.css` -> the next GET returns the new content immediately; ETag changes; `If-None-Match`
  -> 304.
- Setting a per-share CSP -> the response header switches immediately; clearing it -> back to the fallback.
- Deleting the share -> raw 404; the `oc_raw_shares` row is gone.
- A 100 MiB file (chunked upload) -> raw streaming download with matching hash.
- `raw enable --raw-only` -> `raw disable` -> `raw enable` (no flag) -> `rawOnly=false`, CSP kept;
  `raw enable` prints the "fully public" warning on stderr.
- Password-protected link share: public DAV (`/public.php/dav/files/<token>/`) answers 207 with the share
  password and 401 without - the password only protects the `/s/` page and public DAV; raw ignores it
  (section 7).

filehost sandbox runs (cleaned up with `unpublish --delete-files --yes`):

- `publish --prune --dry-run` works before the remote folder exists; `--prune` without `--yes` is refused, with
  `--yes` stale files are deleted.
- Folder with `index.html` -> `csp=preset:site`, content hash matches; re-publish with `--inject-base` ->
  `csp=kept`, and `verify <name> --local <dir>` accepts the injected version.
- Folder without `index.html` -> `url` = `/raw/<token>/<first file by path>` (200, hash matches); `short_url`
  `/raw/<token>` answers 200 `application/json` `null`; `info` reports file count and bytes.
- `url <name> "sub dir/"` -> percent-encoded with the trailing slash kept; that URL answers 200.
- `unpublish --delete-files --yes` -> raw 404, folder in the trash bin.
